# КЕДР — мониторинг лесных пожаров

Веб-платформа для раннего обнаружения лесных пожаров: детекция огня и дыма нейросетью
YOLOv11, расчёт зоны распространения огня, оценка угрозы населённым пунктам и
критической инфраструктуре, формирование PDF-донесений и оповещение диспетчеров МЧС.

- **Backend** — FastAPI + PostgreSQL (SQLite как zero-config fallback) + Alembic.
  Расчёт распространения: Rothermel-подобная модель + клеточный автомат.
- **Frontend** — React 18 + MapLibre GL.

## Возможности

- 🔥 **Детекция огня и дыма** на фото и видео (YOLOv11), покадровая обработка видео и RTSP-потоков.
- 🎚️ **Раздельные пороги для дыма и огня**: дым — раннее предупреждение, поэтому его пороги строже.
- 🗺️ **Карта очагов** по России с поиском любого населённого пункта (локальный справочник + Nominatim).
- 🌬️ **Расчёт зоны распространения** с учётом ветра, влажности, температуры, уклона и типа топлива.
- 🏘️ **Оценка угрозы** населённым пунктам и рекомендации по эвакуации (азимут + ближайшая помощь).
- 🏥 **Критическая инфраструктура рядом** — больницы, пожарные части, АЭС, ГЭС, НПЗ, подстанции, аэродромы (OpenStreetMap / Overpass).
- 🔔 **Три уровня эскалации** — «чисто» (<40%), «проверка лесничим» (40–80%), «критическая тревога» (≥80%) с WebSocket-оповещениями диспетчерам.
- 📄 **PDF-донесения** с координатами, погодой, топливом и таблицей эвакуации.
- 👥 **Роли**: гражданин, лесничий, диспетчер МЧС.
- 🔐 **Безопасность**: bcrypt, JWT с отзывом через `token_version`, подписанные ссылки на медиа, rate-limit, защита от SSRF, проверка контрольной суммы весов.

## Быстрый старт (Docker)

### Требования

- **Docker Desktop 4.30+** или Docker Engine + Compose v2
- **~4 ГБ** свободного места на Apple Silicon / ARM и **~8 ГБ** на x86 (см. ниже)
- **GPU** — опционально

### Архитектура выбирается автоматически

`backend/Dockerfile` — multi-arch: BuildKit подставляет `TARGETARCH`, и один и тот же файл
собирает нужный вариант. Ничего настраивать не нужно.

| Ваша машина | Что соберётся | Размер образа | GPU |
|---|---|---|---|
| **Apple Silicon** (`arm64`) | CPU-сборка `torch` | **≈2.6 ГБ** | нет NVIDIA — и не нужен |
| **x86_64** (`amd64`) | CUDA-сборка `torch` | ≈6–7 ГБ (оценка) | используется, если пробросить GPU |
| ARM-сервер | CPU-сборка `torch` | ≈2.6 ГБ | — |

Наличие GPU определяется на ходу: `YOLO_DEVICE=auto` (по умолчанию) берёт `cuda:0`, если
CUDA доступна, иначе `cpu`. На x86 без GPU всё работает на CPU.

**Что проверено:** arm64-образ собран и прогнан насквозь (55/55 API-проверок дважды),
amd64 CPU-вариант собран и проверен на согласованность `torch`/`torchvision`
(`torchvision.ops.nms` работает). Полная сборка amd64 **CUDA**-варианта в этой среде не
завершалась — только проверен резолв колёс `torch 2.3.1+cu121` и `torchvision 0.18.1+cu121`.

Если CUDA на x86 не нужна и хочется сэкономить ~3.5 ГБ, задайте в `.env`:

```dotenv
TORCH_VARIANT=cpu
```

Чтобы включить GPU на машине с NVIDIA:
1. поставьте драйвер и `nvidia-container-toolkit`;
2. раскомментируйте блок `deploy:` у сервиса `backend` в `docker-compose.yml`;
3. `docker compose up -d` — при `YOLO_DEVICE=auto` модель уйдёт на GPU.

### Шаги

```bash
git clone https://github.com/ARGAMEPRO/KEDER.git
cd KEDR
cp _env.example .env
```

Откройте `.env` и **обязательно задайте `POSTGRES_PASSWORD`** (compose откажется стартовать без него):

```dotenv
POSTGRES_PASSWORD=придумайте-сложный-пароль
```

`SECRET_KEY` в режиме `dev` можно оставить пустым — приложение само создаст стойкий ключ
в `backend/data/dev_secret.key` (файл в `.gitignore`).

```bash
docker compose up -d --build     # первый запуск 5–15 минут
docker compose logs -f backend
```

Откройте:

| Что                  | Адрес                               |
| -------------------- | ----------------------------------- |
| 🌐 Сайт              | http://localhost:5173               |
| 💚 Проверка здоровья | http://localhost:5173/api/v1/health |

> Порт backend (8000) **намеренно не публикуется наружу** — единственная точка входа это
> nginx на 5173. Поэтому Swagger в `dev` доступен только изнутри контейнера:
>
> ```bash
> docker compose exec backend python -c "import urllib.request as u; print(u.urlopen('http://localhost:8000/docs').status)"
> ```

---

### Что обязательно ввести в `.env`

| Что | Зачем | Обязательно? |
|---|---|---|
| `POSTGRES_PASSWORD` | пароль базы, compose без него не стартует | **да** |
| `GEOAPIFY_KEY` | инфраструктура вокруг очага: больницы, пожарные, АЭС, НПЗ | очень желательно |
| веса `best.pt` в `backend/weights/` | детекция огня и дыма на фото и видео | нет, но без них анализ отключён |

**Ключ Geoapify:** https://myprojects.geoapify.com → Create project → скопировать API key.
Бесплатно 3000 кредитов в сутки (≈1500 запросов инфраструктуры), карта не нужна, только e-mail.
Вставьте строкой `GEOAPIFY_KEY=ваш_ключ` — без кавычек и пробелов.

Остальные ключи (`TWOGIS_KEY`, `OPENWEATHER_KEY`) — необязательные резервы, приложение работает и без них.
`SECRET_KEY` в `dev` можно оставить пустым.

### Проверка, что всё поднялось (30 секунд)

```bash
curl -s http://localhost:5173/api/v1/health
# {"status":"ok","model":true,...}  — model:true значит веса загружены

curl -s "http://localhost:5173/api/v1/geo/infrastructure?lat=55.75&lon=37.62&radius_m=15000" \
  | head -c 300
# должны прийти facilities и "source":"geoapify" (или "osm")
```

Если карточка инфраструктуры пустая — проверьте `GEOAPIFY_KEY` в `.env` и перезапустите backend:
`docker compose up -d --force-recreate backend` (после правки `.env` обычный `up -d` может не подхватить значения).

## Как добавить веса нейросети

Без весов сайт работает полностью, кроме анализа изображений: `/analyze` вернёт
**503** с понятным сообщением, а `/api/v1/health` покажет `"model": false`.
Идентификация, карта, инциденты, PDF и оповещения работают.

**Веса можно добавить в любой момент — перезапуск не требуется.** Модель
загружается лениво при первом анализе, и каждый раз проверяется наличие файла.

### Вариант А — положить файл (рекомендуется)

```bash
cp best.pt backend/weights/best.pt
```

Файл сразу виден контейнеру (каталог `backend/weights` смонтирован в `/backend/weights`).
Проверьте: `curl -s http://localhost:5173/api/v1/health` → `"model": true`.

### Вариант Б — автозагрузка по ссылке

```dotenv
YOLO_WEIGHTS_URL=https://example.com/best.pt
YOLO_WEIGHTS_SHA256=<sha256 файла>      # настоятельно рекомендуется
```

Файл скачается при старте. **Обязательно указывайте `YOLO_WEIGHTS_SHA256`**: файл `.pt` —
это pickle, и загрузка непроверенных весов равносильна выполнению произвольного кода.

Получить хеш: `sha256sum best.pt`

### Если модель не нужна на этой машине

Оставьте `backend/weights/` пустым. Ничего не упадёт: анализ вернёт 503,
остальные функции продолжат работать. Это же поведение используется в CI.

## Демо-аккаунты и их удаление

В режиме `dev` при первом запуске создаются три обычные записи в таблице `users`
с флагом `is_demo = true`:

| Роль          | E-mail             | Пароль           |
| ------------- | ------------------ | ---------------- |
| Гражданин     | `citizen@kedr.ru`  | `kedr-demo-1234` |
| Лесничий      | `forester@kedr.ru` | `kedr-demo-1234` |
| Диспетчер МЧС | `mchs@kedr.ru`     | `kedr-demo-1234` |

В интерфейсе нет кнопок «демо-вход»: это обычные аккаунты, которые нужно удалить перед публикацией.
Если вы вошли под демо-аккаунтом, в шапке сайта показывается предупреждение.

### Удаление (обязательно перед продакшеном)

```bash
# удалить демо-аккаунты
docker compose exec backend python -m scripts.manage delete-demo-users

# при необходимости — и созданные ими инциденты
docker compose exec backend python -m scripts.manage purge-demo-incidents

# проверить результат
docker compose exec backend python -m scripts.manage list-users
```

Чтобы демо-аккаунты **не создавались вообще**, в `.env`:

```dotenv
SEED_ON_STARTUP=false
```

Создайте себе рабочую учётную запись диспетчера:

```bash
docker compose exec backend python -m scripts.manage create-user \
  --email boss@example.ru --password 'СложныйПароль1' --role mchs
```

## Чек-лист перед продакшеном

- [ ] `APP_ENV=production` — включает строгие проверки и отключает `/docs`.
- [ ] `SECRET_KEY` — **непустой, ≥32 символов, не из примеров**. Пустое или
      известное значение (например `change-me-in-production`) приводит к **отказу запуска**.
      ```bash
      python -c "import secrets; print(secrets.token_urlsafe(48))"
      ```
- [ ] `POSTGRES_PASSWORD` — сложный и уникальный.
- [ ] `SEED_ON_STARTUP=false` (в production сидирование требует ещё и
      `SEED_ALLOW_IN_PRODUCTION=true`, так что случайно демо-аккаунты не появятся).
- [ ] Демо-аккаунты удалены: `python -m scripts.manage delete-demo-users`.
- [ ] `CORS_ORIGINS` содержит только ваш реальный домен.
- [ ] **TLS**: nginx в комплекте слушает HTTP. Поставьте перед ним TLS-терминатор
      (Traefik / Caddy / облачный балансировщик) — пароли и токены ходят по сети.
- [ ] `SERVE_UPLOADS_PUBLIC=false` (по умолчанию) — медиа отдаётся только по подписанным ссылкам.
- [ ] Настроены резервные копии тома `kedr-pgdata`.
- [ ] `RETENTION_CLEAR_DAYS` / `RETENTION_INCIDENT_DAYS` соответствуют вашей политике хранения.
- [ ] `/api/v1/health` возвращает `{"ok": true, "db": true, "model": true}`.

## Локальная разработка без Docker

Нужен Python 3.10+ (torch/ultralytics не обязательны, чтобы поднять API).

```bash
cd backend
python -m venv ../.venv && source ../.venv/bin/activate
pip install -r requirements-test.txt        # без 2 ГБ torch
# или полностью: pip install -r requirements.txt

export APP_ENV=dev
export SEED_ON_STARTUP=true
# DATABASE_URL не задаём -> SQLite в backend/kedr.db
python -m uvicorn app.main:app --reload --port 8000
```

Фронтенд:

```bash
cd frontend
npm ci
npm run dev        # http://localhost:5173, /api проксируется на localhost:8000
```

Схема БД создаётся и миграции применяются автоматически (Alembic) при старте.

## Управление пользователями и данными (CLI)

Запускается из каталога `backend/` (в контейнере — через `docker compose exec backend`).

| Команда | Назначение |
|---|---|
| `python -m scripts.manage list-users` | список пользователей (роль, демо-флаг, активность) |
| `python -m scripts.manage create-user --email E --password P --role {citizen,forester,mchs}` | создать пользователя |
| `python -m scripts.manage delete-demo-users` | удалить демо-аккаунты |
| `python -m scripts.manage purge-demo-incidents` | удалить инциденты демо-аккаунтов |
| `python -m scripts.manage set-role --email E --role R` | сменить роль (и отозвать токены) |
| `python -m scripts.manage reset-password --email E --password P` | сменить пароль (и отозвать токены) |
| `python -m scripts.manage deactivate --email E` | отключить учётную запись |
| `python -m scripts.manage stats` | краткая статистика по базе |
| `python -m scripts.manage reset-db --yes` | пересоздать схему (**удаляет все данные**) |

## Переменные окружения

Полный список с комментариями — в [`_env.example`](_env.example). Ключевые:

| Параметр | Назначение | По умолчанию |
|---|---|---|
| `APP_ENV` | `dev` / `production` | `dev` |
| `SECRET_KEY` | ключ подписи JWT. В `dev` можно пусто (создастся файл), в `production` обязателен и ≥32 символов | — |

| `TIER_PENDING`, `TIER_CRITICAL` | пороги эскалации для огня | `0.40`, `0.80` |

| `MAX_UPLOAD_MB` | лимит загрузки | `100` |
| `RATE_LIMIT_PER_MIN`, `RATE_LIMIT_LOGIN`, `RATE_LIMIT_REGISTER` | лимиты запросов | `10`, `10`, `8` |
| `SERVE_UPLOADS_PUBLIC` | отдавать ли медиа по публичному `/uploads` | `false` |
| `RETENTION_CLEAR_DAYS` | удалять CLEAR-инциденты старше N дней (`0` — не удалять) | `14` |
| `ENABLE_FIRE_BARRIERS` | запрашивать дороги/реки как информацию о барьерах | `false` |
| `SEED_ON_STARTUP`, `SEED_PASSWORD` | демо-данные | `true`, `kedr-demo-1234` |
| `LOG_LEVEL` | уровень логов | `INFO` |

## API

Базовый префикс — `/api/v1`.

### Аутентификация

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| POST | `/auth/register` | все | регистрация: `email`, `password`, `password_confirm`, `full_name`. Роль всегда `citizen` |
| POST | `/auth/login` | все | вход, возвращает JWT |
| GET | `/auth/me` | любая роль | текущий пользователь |
| POST | `/auth/change-password` | любая роль | смена пароля; **отзывает все выданные токены** |
| POST | `/auth/logout` | любая роль | отзыв токена |

### Инциденты

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| POST | `/incidents/report` | все (видео — только с токеном) | загрузка фото/видео |
| POST | `/incidents/manual` | МЧС | ручной инцидент без фото |
| POST | `/incidents/manual-photo` | лесничий, МЧС | инцидент с фото; `verdict` = `auto`/`confirm`/`critical` |
| POST | `/incidents/rtsp` | МЧС | анализ RTSP/HTTP-потока (с защитой от SSRF) |
| GET | `/incidents/public` | все | публичная лента (без геометрии) |
| GET | `/incidents` | лесничий, МЧС | лента с пагинацией, компактный payload |
| GET | `/incidents/{id}` | лесничий, МЧС | полная карточка, включая геометрию ячеек |
| GET | `/incidents/general-report` | лесничий, МЧС | агрегированная сводка |
| GET | `/incidents/{id}/report.pdf` | МЧС | PDF-донесение |
| POST | `/incidents/{id}/review` | лесничий, МЧС | `confirm` / `false_alarm` |
| POST | `/incidents/{id}/refresh` | лесничий, МЧС | пересчитать обогащение |
| PATCH | `/incidents/{id}/location` | гражданин (свой), персонал | уточнить координаты |
| DELETE | `/incidents/{id}` | лесничий, МЧС | удалить инцидент и файлы |

### Гео, медиа, служебное

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| GET | `/geo/search?q=` | все | поиск населённого пункта |
| GET | `/geo/weather?lat=&lon=` | все | текущая погода |
| GET | `/geo/infrastructure?lat=&lon=&radius_m=` | все | инфраструктура рядом |
| GET | `/media/{path}?token=` | подписанная ссылка | приватная отдача загруженных файлов |
| GET | `/health` | все | статус БД и модели |
| WS | `/ws/alerts` | лесничий, МЧС | поток оповещений |

**WebSocket**: подключение с подпротоколом `kedr.v1`, затем первым кадром
`{"type":"auth","token":"<JWT>"}`. Токен не попадает в URL и логи прокси.

**Поток обработки инцидента**: загрузка → стриминг во временный файл с лимитом →
детекция (в thread pool) → классификация по классу и уверенности → запись кадра →
параллельный сбор контекста (погода, регион, населённые пункты, инфраструктура) →
расчёт зоны (thread pool) → план эвакуации → WebSocket-оповещение.

## Поток обработки фото

1. Загрузка с реальным прогрессом (XHR), затем «обработка нейросетью».
2. Показывается **обработанный снимок** с выделенными огнём и дымом, класс и уверенность.
3. Координаты съёмки берутся из EXIF и **запрашивается подтверждение** («Это место съёмки?»),
   с возможностью уточнить поиском по населённому пункту, вводом координат или геопозицией.
4. Если EXIF пуст — КЕДР прямо об этом сообщает и **требует указать точку**, иначе инцидент не создаётся.
5. Только после подтверждения создаётся инцидент (`POST /incidents/analyze` → `POST /incidents/confirm`).

**Оптимизация хранения.** Оригиналы не сохраняются в полном весе: кадр уменьшается до
`IMAGE_MAX_WIDTH` (1600 px) и перекодируется в JPEG с качеством `IMAGE_JPEG_QUALITY` (82),
плюс делается миниатюра `THUMB_WIDTH` (320 px). Черновики живут `DRAFT_TTL_SEC` и удаляются
автоматически.

## Спутник и видеотрансляции

**Спутник — NASA FIRMS** (бесплатно, нужен только ключ):
```bash
python -m scripts.import_firms --bbox 60,50,120,75 --days 1        # разовый импорт
```
Или задайте `FIRMS_MAP_KEY` и `FIRMS_POLL_MINUTES=30` — сервер сам будет подтягивать
термоточки MODIS/VIIRS и создавать инциденты с источником `SATELLITE`.
Повторные опросы не плодят дубликаты (`FIRMS_DEDUPE_KM`).

**Живая трансляция — RTSP/HTTP** (IP-камера, дрон, видеосервер):
`POST /api/v1/incidents/rtsp` с `{"url": "rtsp://…", "lat": …, "lon": …, "seconds": 30}`
(роль MCHS). Кадры сэмплируются с `FRAME_SAMPLE_FPS`, поток ограничен
`STREAM_MAX_SECONDS`, адрес проверяется на SSRF.

## Физика расчёта

Код (`backend/app/fire_model.py`) реализует стандартные модели, а не подогнанные константы.

| Что | Модель | Источник |
|---|---|---|
| Скорость распространения | Rothermel (1972), в оригинальных единицах | INT-115 |
| Параметры топлива | Anderson, модели 1/2/3/8/10 | INT-122 |
| Влажность тонкого топлива | Equilibrium moisture content по T и RH | Simard (1968) |
| Форма очага | Эллипс, длина/ширина по ветру в приземном слое | Anderson (1983), INT-305 |
| Ветер в приземном слое | Лог-профиль 10 м → 20 футов + wind adjustment factor | Andrews (2012), RMRS-GTR-266 |
| Интенсивность и пламя | Byram (1959): I = H·w·R, L = 0.0775·I^0.46 | — |

Уравнения Rothermel считаются в тех единицах, для которых определены их коэффициенты
(σ в ft⁻¹, ветер в ft/min, нагрузки в lb/ft²) — смешение единиц молча меняет ответ,
поэтому перевод в СИ делается только в самом конце. Волновой фронт — эллипс с очагом
в заднем фокусе: `r(θ) = r_head·(1−e)/(1−e·cos θ)`, где `e` из отношения длины к ширине
по Anderson.

**Проверка:** для модели FM8 при влажности 8% без ветра модель даёт 0.37 ft/min —
совпадает с эталонными значениями BehavePlus (~0.4 ft/min).

В ответе API и в PDF теперь есть: `fuel_model`, `fuel_moisture`, `ros_m_per_min`,
`wind_midflame_ms`, `length_to_breadth`, `eccentricity`, `fireline_intensity_kw_m`,
`flame_length_m`, `intensity_class`, `burn_minutes`.

### Что остаётся моделью, а не истиной

- **Окно расчёта** (`HAZARD_BURN_MINUTES`, по умолчанию 180 мин) — это сценарий
  «сколько пожар горит без тушения», а не физика. Это самый влиятельный параметр
  на размер зоны, поэтому он явно вынесен в настройки и возвращается в API.
- **Уклон** задаётся эвристикой по типу ландшафта (`SLOPE_*_DEG`), а не цифровой моделью
  рельефа: для настоящего расчёта нужен DEM.
- **Город** описывается моделью FM8 с коэффициентом разрывности топлива 0.4
  (`URBAN_CONTINUITY`). В Rothermel нет понятия разрывности топлива, а горение
  «здание к зданию» этот класс моделей не описывает вообще — это явный суррогат,
  а не коэффициент модели.
- **Дороги и реки** (`check_fire_barriers`) отдаются как справка и **не влияют** на полигон
  (по умолчанию запрос выключен: `ENABLE_FIRE_BARRIERS=false`).
- **План эвакуации** — рекомендуемый азимут (перпендикулярно оси ветра), расстояние и
  ближайшие больница/пожарная часть, а **не маршрут** по дорогам.
- **Пороги эскалации** — уверенность детектора, а не вероятность пожара.
- **Живое топливо** (кроны, кустарник) не моделируется: это модель напочвенного горения
  по мёртвому топливу, поэтому вершинные пожары она не описывает.

## Решение проблем

| Проблема | Решение |
|---|---|
| `POSTGRES_PASSWORD must be set in .env` | задайте `POSTGRES_PASSWORD` в `.env` |
| `SECRET_KEY ... Refusing to start` | в `production` задайте стойкий `SECRET_KEY` (≥32 символа) |
| `Cannot connect to the Docker daemon` | запустите Docker Desktop |
| Порт 5173 занят | поменяйте в `docker-compose.yml`: `"5174:80"` |
| `health` показывает `"model": false` | положите `best.pt` в `backend/weights/` (перезапуск не нужен) |
| `503 Веса модели не найдены` | то же самое; проверьте `YOLO_WEIGHTS` |
| `503 ultralytics/torch не установлена` | установите зависимости из `backend/requirements.txt` |
| Анализ очень медленный | нет GPU: `YOLO_DEVICE` определится как `cpu`. Так и задумано |
| Образ backend занимает 13 ГБ | Это старая сборка на базе CUDA. Пересоберите: `docker compose build backend` — на arm64 образ станет ~2.6 ГБ |
| Сообщение «platform (linux/amd64) does not match (linux/arm64)» | Образ собран под другую архитектуру. Удалите его и пересоберите: `docker compose build --no-cache backend` |
| «Сервис OSM недоступен» | Overpass лежит или блокируется. Увеличьте `OVERPASS_TIMEOUT`, проверьте `OVERPASS_URLS` |
| Инцидент создаётся долго | внешние сервисы (Overpass/Nominatim) медленные; расчёт вынесен в thread pool |
| Токен перестал работать | это нормально после смены пароля/выхода — `token_version` отозвал старые токены |

## Работа из России: карта, поиск, инфраструктура

`overpass-api.de`, `nominatim`, `openfreemap`, `Esri` и `Open-Meteo` из российских
сетей отдают 406/502/RST, поэтому каждый внешний слой имеет резервную цепочку.
Порядок — от бесплатного и локального к платному и удалённому; первый успешный
ответ выигрывает, последний удачный кладётся на диск и переживает любую блокировку.

| Слой | 1-й выбор (без ключа) | 2-й | 3-й | Кэш |
|---|---|---|---|---|
| Подложка карты | Яндекс-тайлы `core-renderer-tiles` | тайлы 2ГИС | — | тайлы браузера |
| Спутник | Яндекс `core-sat` | — | — | тайлы браузера |
| Поиск населённых пунктов | локальная база `ru_cities.json` | Яндекс suggest (без ключа) | Nominatim | — |
| Регион по точке | Nominatim | ближайший город из локальной базы | — | 30 дней |
| Инфраструктура | Overpass (если доступен) | Geoapify (`GEOAPIFY_KEY`) | 2ГИС (`TWOGIS_KEY`) | 30 дней |
| Погода | Open-Meteo | met.no | OpenWeather (`OPENWEATHER_KEY`), wttr.in | 1 день |

Free-ключи занимают пару минут: [geoapify.com](https://www.geoapify.com/) —
MyProjects → API key (бесплатный тариф ~3000 кредитов/сутки, данные OSM);
[dev.2gis.ru](https://dev.2gis.ru/) — demo-ключ Catalog API. Без ключей панель
инфраструктуры работает на Overpass и на сохранённом кэше.

Если нужен именно OSM-качество и полный охват, поставьте бесплатный релей
(`deploy/overpass-relay/worker.js`, Cloudflare Workers, 100 000 запросов/сутки):
он проксирует Overpass снаружи блокировки, а в `.env` достаточно указать его URL
первым в `OVERPASS_URLS`.

## Безопасность

Реализовано:

- **Пароли** — bcrypt; политика: минимум 8 символов, буква и цифра; ограничение длины
  (bcrypt использует только первые 72 байта — более длинные пароли отклоняются, а не обрезаются).
- **JWT** — HS256, проверка `aud`/`iss`/`exp`/`nbf`, отзыв через `token_version`
  (смена пароля и выход инвалидируют все ранее выданные токены).
- **Секреты** — при `APP_ENV=production` пустой или известный `SECRET_KEY` приводит к отказу запуска.
- **Роли** — назначаются только на сервере; клиент не может выбрать роль при регистрации.
- **Медиа** — загруженные файлы приватны и отдаются по подписанным ссылкам с ограниченным TTL;
  публичный `/uploads` выключен по умолчанию.
- **Rate limit** — на всех чувствительных и «дорогих» эндпоинтах; IP вычисляется с учётом
  доверенных прокси, подделанный клиентом `X-Forwarded-For` игнорируется.
- **SSRF** — RTSP/HTTP-URL проверяется по схемам и адресам, внутренние и служебные
  диапазоны запрещены.
- **Загрузки** — лимит размера, проверка MIME, стриминг во временный файл, удаление после обработки.
- **Веса модели** — опциональная проверка SHA-256 перед загрузкой, лимит размера.
- **Пути** — доступ к файлам ограничен каталогом `uploads` (защита от обхода каталога).
- **Сеть** — backend не публикуется наружу, доступен только через nginx; в production `/docs` и
  `/openapi.json` отключены.
- **Заголовки** — `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`,
  `Permissions-Policy`, CSP на уровне nginx.

Осознанные ограничения: нет подтверждения e-mail, нет MFA, нет восстановления пароля по почте
(сброс — через CLI администратором), нет шифрования данных в БД, in-process rate-limit и
WebSocket-хаб рассчитаны на один процесс (для нескольких реплик нужен Redis).
