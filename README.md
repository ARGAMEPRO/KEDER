# КЕДР — мониторинг лесных пожаров

**КЕДР** — веб-платформа для раннего обнаружения лесных пожаров с помощью нейросети YOLOv8, расчёта зоны распространения огня, оценки угрозы населённым пунктам и построения плана эвакуации.

Проект состоит из:
- **Backend** — FastAPI + YOLOv8 + PostGIS-совместимая БД (SQLite), расчёт распространения пожара по модели Rothermel и клеточному автомату.
- **Frontend** — React + MapLibre GL, карта России, поиск городов, панели для граждан / лесничих / диспетчеров МЧС.

---

## Возможности

- 🔥 **Обнаружение огня и дыма** на фото и видео (YOLOv8), покадровая обработка видео.
- 🗺️ **Карта очагов** по всей России с поиском любого населённого пункта.
- 🌬️ **Расчёт зоны распространения** с учётом ветра, влажности, температуры, рельефа и типа топлива (лес / город / смешанный).
- 🏘️ **Оценка угрозы населённым пунктам** и построение маршрутов эвакуации.
- 🏥 **Критическая инфраструктура рядом** — больницы, пожарные части, АЭС, ГЭС, НПЗ (данные OpenStreetMap / Overpass).
- 🔔 **Три уровня эскалации** — «чисто» (<40%), «проверка лесничим» (40–80%), «критическая тревога» (≥80%) с WebSocket-оповещениями диспетчерам МЧС.
- 📄 **PDF-донесения** с координатами, погодой, топливом, таблицей эвакуации.
- 👥 **Роли пользователей** — гражданин, лесничий, диспетчер МЧС.

## Требования

- **Docker Desktop 4.30+** (Windows / macOS) или Docker Engine + Compose v2 (Linux)
- **6 ГБ свободного места** (образ backend с PyTorch ~5 ГБ)
- **GPU** — опционально, но без него анализ медленный. Для NVIDIA нужен драйвер + nvidia-container-toolkit.
- **Веса модели** `yolov8x-fire.pt` — скачиваются автоматически при первом запуске (см. ниже).

## Установка Docker

### Windows

1. Скачай **Docker Desktop for Windows**: https://www.docker.com/products/docker-desktop/
2. Запусти установщик. На этапе выбора компонентов **оставь галочку «Use WSL 2 instead of Hyper-V»** — это быстрее и стабильнее.
3. Если WSL 2 не установлен, установщик предложит установить его автоматически — согласись.
4. После установки **перезагрузи компьютер**.
5. Запусти **Docker Desktop** из меню «Пуск». Дождись, пока в трее появится зелёный значок кита (может занять 1–2 минуты).
6. Проверь в PowerShell или cmd:
   ```
   docker --version
   docker compose version
   ```
   Обе команды должны вывести версии.

### macOS

**Для Mac на Apple Silicon (M1/M2/M3/M4):**

1. Скачай **Docker Desktop for Mac (Apple Silicon)**: https://www.docker.com/products/docker-desktop/
2. Открой `.dmg`, перетащи иконку в **Applications**.
3. Запусти Docker из Launchpad / Applications.
4. Первый запуск попросит разрешения (Keychain, доступ к сети) — согласись.
5. Дождись, пока в строке меню появится значок кита с зелёным статусом.
6. Проверь в Terminal:
   ```bash
   docker --version
   docker compose version
   ```

**Для Mac на Intel:** то же самое, но скачивай **Docker Desktop for Mac (Intel Chip)**.

> ⚠️ **На macOS нет поддержки CUDA** — YOLO будет работать на CPU. Это медленнее (5–15 с на кадр), но всё работает. Для GPU используй Linux или Windows с NVIDIA.

## Запуск проекта

### 1. Клонируй репозиторий

```bash
git clone https://github.com/ARGAMEPRO/KEDER.git
cd KEDER
```

### 2. Создай файл окружения

**macOS / Linux:**
```bash
cp _env.example .env
```

**Windows (PowerShell):**
```powershell
Copy-Item _env.example .env
```

**Windows (cmd):**
```cmd
copy _env.example .env
```

Открой `.env` в любом редакторе. Для локального запуска менять ничего не нужно.

### 3. Положи веса модели

**Вариант А (рекомендуется):** веса скачаются автоматически при первом запуске, если в `.env` указан `YOLO_WEIGHTS_URL` (он уже прописан по умолчанию).

**Вариант Б:** скачай `yolov8x-fire.pt` вручную и положи в `backend/weights/yolov8x-fire.pt`.

> Без весов сайт запустится, но `/analyze` вернёт «модель не загружена», и анализ фото будет недоступен.

### 4. Запусти контейнеры

```bash
docker compose up -d --build
```

Первый запуск займёт **5–10 минут** — скачиваются образы PyTorch и Node, собирается frontend.

### 5. Открой в браузере

- 🌐 **Сайт:** http://localhost:5173
- 📚 **API-документация (Swagger):** http://localhost:8000/docs
- 💚 **Проверка здоровья:** http://localhost:8000/api/v1/health

## Полезные команды

```bash
# Остановить контейнеры
docker compose down

# Остановить и удалить все данные (БД, загруженные фото)
docker compose down -v

# Перезапустить только backend после правок кода

# Полная пересборка после изменения Dockerfile / requirements.txt
docker compose up -d --build
```

## Настройка (`.env`)

Все параметры в `_env.example` с комментариями. Ключевые:

| Параметр | Что делает |
|---|---|
| `SECRET_KEY` | Секрет для JWT. **Обязательно поменяй в продакшене!** |
| `APP_ENV` | `dev` — сидит демо-данные, `production` — требует сильный `SECRET_KEY` |
| `YOLO_DEVICE` | `cuda:0` для GPU, `cpu` для CPU |
| `YOLO_WEIGHTS_URL` | Ссылка на файл весов, скачается при первом запуске |
| `MAX_UPLOAD_MB` | Лимит размера загружаемого файла (по умолчанию 100 МБ) |
| `OVERPASS_TIMEOUT` | Таймаут запросов к OpenStreetMap (увеличь до 30–45 с, если часто «нет инфраструктуры») |

## Частые проблемы

| Проблема | Решение |
|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop не запущен — открой его и дождись зелёного значка |
| Порт 5173 или 8000 занят | Поменяй в `docker-compose.yml` (например `"5174:80"`) или закрой приложение, занимающее порт |
| «Модель обнаружения не загружена» | Веса не скачались. Проверь `backend/weights/`, или скачай вручную |
| «Сервис OSM недоступен» при поиске города | Overpass лежит или блокируется провайдером. Увеличь `OVERPASS_TIMEOUT=45` и оставь рабочее зеркало в `OVERPASS_URLS` |
| Backend падает с `SECRET_KEY` | При `APP_ENV=production` нужен `SECRET_KEY` длиной >20 символов |
| На macOS анализ очень медленный | Это норма — нет CUDA. Для GPU переходи на Linux / Windows с NVIDIA |
