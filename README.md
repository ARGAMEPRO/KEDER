# КЕДР — мониторинг лесных пожаров

## Запуск
```bash
copy .env.example .env         # Windows (Linux/macOS: cp)
docker compose up -d --build   # сайт http://localhost:5173, API http://localhost:8000/docs
```
Демо-входы (только dev): forester@kedr.ru, mchs@kedr.ru — пароль `123456`.

## Модель обнаружения (без неё анализ фото недоступен)
Положите веса в `backend/weights/yolov8x-fire.pt` **или** задайте `YOLO_WEIGHTS_URL` в `.env`.
Состояние модели: `GET /api/v1/health` → `"model": true/false`.

## Продакшен
`APP_ENV=production`, длинный `SECRET_KEY`, `SEED_ON_STARTUP=false`, HTTPS на внешнем прокси.
Лимиты: `MAX_UPLOAD_MB`, `RATE_LIMIT_PER_MIN`. Для нескольких реплик вынесите лимитер в Redis.

## Проверка
`GET /api/v1/geo/weather?lat=56&lon=92.9` показывает реальную погоду или причину ошибки.
Тесты логики: `docker compose run --rm backend sh -c "pip install pytest && pytest tests"`.

## Что нового (последняя итерация)

1. **Откуда координаты** — у инцидента теперь есть `gps_source` (`EXIF` / `DEVICE` / `MANUAL` / `NONE`);
   бейдж видно в карточке, а рядом с очагом без GPS есть кнопка «Уточнить место»
   (поиск населённого пункта, геопозиция, ручные широта/долгота) → `PATCH /incidents/{id}/location`
   проставляет `gps_source=MANUAL` и пересчитывает зону.
2. **Лесничий видит всё** — вкладка «Все» с `GET /incidents?include_clear=1` показывает и очаги без GPS,
   и «Чисто» (near-miss), чтобы их можно было проверить и уточнить место.
3. **Открытая регистрация** — `POST /auth/register`: любой становится `CITIZEN`, роль с клиента не принимается,
   почта нормализуется, пароль ≥ 8 символов с буквой и цифрой, дубликат → 409 (включая гонку),
   лимит 8 запросов/мин.
4. **Скорость** — список зеркал Overpass (`OVERPASS_URLS`), таймаут с переключением зеркала, TTL-кэши
   (погода, геокодинг, населённые пункты, инфраструктура) и параллельный `enrich()` через `asyncio.gather`.
5. **Новый инцидент вручную** — пошаговая форма; лесничий обязан приложить фото,
   у диспетчера МЧС есть выбор вердикта «Подтвердить пожар» / «Критическая тревога».
6. **Модель распространения** — Rothermel-подобная скорость + клеточный автомат (волновой фронт Дейкстры,
   шаг 100 м) с отдельными моделями топлива `forest` / `mixed` / `urban`, учётом ветра, влажности и температуры.
   Городская застройка тушит распространение: при ветре 8 м/с фронт ~4 км против ~16 км в лесу.
7. **Инфраструктура на карте (МЧС)** — поиск города показывает на карте и в панели пожарные части, скорую,
   больницы, поликлиники, полицию, школы, детсады, аптеки, укрытия, водозаборы, энергообъекты и промзону;
   в ответе `/geo/infrastructure` есть агрегат `counts`.
8. **Спутник** — кнопка переключения базового слоя «Схема / Спутник» (Esri World Imagery) в правом нижнем углу карты.

Настройки перечисленного — в `_env.example` (`OVERPASS_URLS`, `OVERPASS_TIMEOUT`, `OVERPASS_CONCURRENCY`,
`WEATHER_TTL`, `GEOCODE_TTL`, `NEAR_TTL`, `INFRA_TTL`, `CACHE_MAX`, `CLEAR_DEDUPE_KM`).
